## Known limitations (not defects)
- Answer keys and explanations ship in the file (needed for offline scoring); production scores server-side.
- Orientation change: layout is fluid; no orientation-specific code (verified by width tests only).
- Manual keyboard/screen-reader pass was done by construction and inspection, not by an assistive-technology user.
- The range and rank are illustrative estimates from a prototype mapping and are labelled as such on the screen ("illustrative estimate from the prototype's mapping, not a measured rank"); the curve is captioned "Illustrative scale, not a measured distribution"; the band cut-points (85 / 70 / 40%) are prototype choices, not norms.
- The polyomino item (S1) is not answerable by screen reader (its options are described only as four-square figures); the fold items are, since v4.
- The arrow keys inside the answer group move focus without selecting, a deliberate departure from the ARIA radio pattern because selection auto-advances the quiz.
- Two-tab conflicts are not handled (the last write wins); the prototype is single-tab.
